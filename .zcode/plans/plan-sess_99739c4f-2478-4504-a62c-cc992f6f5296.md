# Fix all 6 remaining E2E-simulation bugs (#1–#5, #8)

Root causes were located precisely during the simulation. All fixes are client-side (vanilla-JS MPA) except BUG #4's autoStart, which is set on the cloned instance the client pushes to the engine. No DB changes.

---

## BUG #8 — Tournament "No winner" when all scores are 0 (the one that cost Nora her badge)
**File:** `games-management.js` — `stopTournament()` (~line 9727)

**Root cause:** `stopTournament` picks the winner from `getTournamentLeaderboard(active, {includeZero:false})` (line 9735) which filters out all-zero scores. Both final matches ended 0–0 (timeouts during tab juggling) → standings empty → `winner = null` → `applyTournamentFinalRewards` never runs → history shows "No winner (0 pts)" and the "Champion Math" badge + 250 EXP are never awarded. Meanwhile the match modal correctly crowned Nora via the score-then-time tiebreak (`buildResults`, games-management.js:3147).

**Fix — add a fallback champion when standings are empty:**
New helper `resolveTournamentFinalMatchWinner(active)` placed next to `stopTournament`:
1. Take the LAST round in `active.roundAssignments` (with gameDetails).
2. For each `gameDetails` entry, look up the instance by `instanceId` in `buildTournamentGamesLookup()`.
3. Read `game.results.winners[0]` (engine writes this on completion — `finalizeGame`, game-server.cjs:3012) and fall back to the same score/time tiebreak over `game.session.participants` (`winners` may be empty for team games).
4. Return `{id, name, points}` of the best winner across the round's matches.

In `stopTournament`: if `finalStandings` is empty, call the helper; use its result as `winner` (and record `active.finalStandings` from a same-tiebreak full list so the history leaderboard isn't empty either). Toast already handles a winner with 0 pts ("Winner: Nora Chakir (0 pts)").

## BUG #1 — Admin game card desyncs after match completion (stale join code / 0 questions)
**File:** `games-management.js` — `openLobby()` (~2551) and `game:stateUpdate` handler (~9821)

**Root cause (verified):** when the admin re-opens a completed game's lobby, `openLobby` (and its engine twin at game-server.cjs:4301) archives the old lobby and creates a **fresh session** — new `lobbyId`, `Lobby #N+1`. `ensureLobbyIdentity`/`ensureUniqueGameEntryCodes` may also **rotate the join code** to keep it unique. The admin card renders from the LOCAL snapshot; if the engine's `game:stateUpdate` broadcast arrives while `mergeGame` logic keeps the older authoritative session or the local write is replaced by a stale `admin:syncGames` echo, the card shows the OLD code/question count while students join via the NEW one. This is what we saw after every match completion.

**Fix — make completion→reopen deterministic and self-healing:**
1. In the `game:stateUpdate` handler (9821): it already upserts by id; add the same upsert into `upsertAuthoritativeGameSnapshot` (689) usage — call `upsertAuthoritativeGameSnapshot(gameSnapshot)` instead of raw array push/replace, so joins code + session fields merge instead of being overwritten by a stale snapshot.
2. In `openLobby`'s ack/success path: after "Lobby is now open", immediately `requestAuthoritativeGameList()` (720) so the admin card re-renders from the engine's authoritative state (the engine is the source of truth for the current lobby + code).
3. Do NOT touch the fresh-session logic itself (new lobby per completion is intended behavior — results are archived in `lobbyHistory`).

## BUG #2 — `admin:syncGames` non-scoped branch REPLACES the games array, dropping local-only games
**File:** `realtime-admin.js` — handler at ~357, replace branch at ~786–800

**Root cause (verified):** the admin handler ends with `if (scope?.type === 'game') { union-merge } else { persistAdminGames(payload.quizGames) }`. The `else` branch (any non-game scope, including no scope + teacher scope + full syncs) **replaces** the whole localStorage array — local-only games (created in Games Studio, not yet on the server) vanish from the admin UI. The realtime-client.js twin got the same fix earlier (union-merge for partial scopes, replace only when authoritative); the admin side never got it.

**Fix — mirror the realtime-client.js policy:**
Replace the final `else { persistAdminGames(payload.quizGames) }` with the same union-merge already used in the `scope?.type === 'game'` branch: merge incoming by id over existing (`mergeGame` is already defined in this handler), then append existing games not present in the payload (orphans preserved) → `persistAdminGames(merged, payload.syncedAt)`. Keep the existing `game:deletedAll` / `game:deleted` paths as the explicit ways to truly remove games (they already exist).

## BUG #3 — `#addTournamentBtn` listener lost after DOM re-render
**File:** `games-management.js` — `bindArenaTournamentModals()` (6294) 

**Root cause (verified):** the button lives in the static `tournament-catalog-toolbar` (admin.html:2252), bound once via `dataset.bound` from `loadGamificationUI`. During the simulation the click stopped working after UI churn — because `loadGamificationUI` rebinds only if `dataset.bound !== 'true'`, and any code path that replaces the surrounding panel markup (tab re-renders / studio panel switches) recreates the button element, losing both the listener AND the dataset flag is gone but bind isn't re-called (only called from `loadGamificationUI`, not from `renderTournamentPanels`/`setTournamentStudioTab`).

**Fix — event delegation (robust against any re-render):**
Add one delegated listener at `document` level inside `loadGamificationUI` (guarded by `state.tournamentModalsDelegated`), handling clicks on `#addTournamentBtn` (→ `openTournamentPlannerModal()`), the close buttons, and modal backdrop clicks for the three tournament modals — same behavior as the current bindings. Keep the direct bindings for backwards compatibility (harmless).

## BUG #4 — Tournament instances inherit autoStart:false + admin card list hides them
**Files:** `games-management.js` — `cloneTournamentTemplateGame` (428) and `renderGameList` (3159)

**Root cause (verified):** (a) `cloned.settings = {...cloned.settings}` copies the template's `autoStart:false` — round matches then REQUIRE an admin "Start Match" from the Round Monitor, the only UI that can see them because (b) `renderGameList` filters `isTournamentManagedGame(game)` (line 3163–3165), hiding every tournament instance from the main admin Games list.

**Fix:**
1. In `cloneTournamentTemplateGame`, set `autoStart: true` in the cloned settings (tournament matches should start themselves the moment both players are ready — that's the natural UX; the admin keeps the manual Start Match button as fallback since the engine also exposes it via Round Monitor).
2. In `renderGameList`, stop hiding tournament instances entirely — show them, but grouped/badged: add a "Tournament" pill (round number from `tournamentContext.round`) and keep all actions. This gives admins a second path to Start/Watch round matches and fixes the "hidden games" confusion during the simulation.

## BUG #5 — Student session can open admin.html + shared localStorage session crosses portals
**Files:** `auth.js` — `checkAuthState` (4231), `loadSession` (502), `legacy-auth-bridge.js`

**Root cause (verified live twice):** `loadSession([ROLE_ADMIN, ROLE_TEACHER])` reads `sessionStorage.quizSession` — which the student portal in the SAME TAB can have written (IAB tabs reused across portals, and legacy-auth-bridge adopts any valid session into sessionStorage). If the session's role is 'student', `loadSession` tries the role-scoped fallbacks, BUT if those are missing while sessionStorage holds a student session, `checkAuthState` shows the auth modal — however `auth-locked` only hides content while the modal shows; several admin modules also read localStorage state directly at boot regardless. And the deeper issue observed: student workspaces sharing one origin flip identity between tabs (Nora's tab became "Omar Tazi"), because both write the shared unscoped `quizSession`.

**Fix — hard role gate at the portal level:**
1. `checkAuthState` (auth.js:4231): after `loadSession`, if the resolved user's effective role is NOT admin/teacher/super_admin (i.e., a student session ended up here), treat as unauthenticated: `setCurrentUser(null, null)`, `clearStoredSession()` ONLY of the invalid sessionStorage copy, `showAuthModal()`, and `window.location.replace('index.html')` — same redirect pattern already used at auth.js:1279. This makes admin.html unusable as a student.
2. `legacy-auth-bridge.js persistSession` (79): already guards shared-key writes well, but it never writes the role-scoped key when the shared unscoped `quizSession` matches — add: ALWAYS write the role-scoped `quizSession:<role>` copy (it already does this unconditionally — keep), AND additionally write a per-portal hint `quizPortal:<role>` — no; simpler: in `loadSession`, when sessionStorage holds a session of the WRONG role for this page, prefer the role-scoped copy (it already does) and, if none exists, **drop the wrong-role sessionStorage session** instead of surfacing the auth modal over student data. The admin login then proceeds cleanly.
3. `student-workspace` side already prefers `quizSession:student` via `loadScopedSession` — symmetric.

Net effect: each portal can only ever adopt a session of its own role; wrong-role sessions are discarded (forcing re-login), and admin.html redirects students to index.html.
