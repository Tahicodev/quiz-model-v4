## 1. Game Type dropdown — show only the 6 types + stop the preset multiplication

**Root cause (verified):** `#gameType` (admin.html:1739) is populated from the `game_presets` store (games-management.js:5213 `loadGamePresets`). The 6 default presets use client ids `default-race`… — the bulk sanitizer (bulk.routes.js:817) strips non-UUID ids, so **every sync cycle creates 6 fresh UUID rows server-side**; the next bootstrap returns those rows, `ensureDefaultGamePresets` (games-management.js:5146) re-normalizes them back to `default-race` ids, sees a diff, and re-syncs → infinite row multiplication (66 dup options observed). Custom presets are also never deduped by name.

**Fixes:**
- `games-management.js`
  - `ensureDefaultGamePresets`: match defaults by `is_default + game_type` (not only id) so server UUID ids are preserved on round-trip → the normalized output equals the raw store → no re-sync loop. Dedupe: keep ONE default row per game_type (newest) and dedupe custom presets by `name+gameType+gameMode` (case-insensitive, keep newest).
  - Create-game modal: **Game Type select shows only the 6 canonical types** (from GAME_TYPE_ORDER/GAME_TYPE_LABELS). New optional **Rules preset dropdown** (`#gameRulesPreset`) next to it, populated with presets filtered to the selected type, default preset pre-selected; `applyGamePresetToForm` fills the rules from it. `getSelectedGamePreset()`/save flow updated to read type + preset separately; games keep storing `type` + rules (current behavior).
- `src/backend/routes/bulk.routes.js` — `game_presets` upsert loop becomes self-healing: before create, `findFirst({ school_id, name, game_type })`; if found reuse its id (update); if multiple exist keep newest and `deleteMany` the rest. This clears the existing 66 dupes on first write — no manual DB surgery needed.
- Presets management UI (Settings → Presets) unchanged.

## 5. AI generation tab — admin-managed models, teacher selection, per-session privacy

Today: 100% client-side, key in one browser's localStorage, teachers can't see admin's models, and OpenRouter/DeepSeek are actually CSP-blocked. **All provider calls move server-side** (fixes CSP + confidentiality + sharing).

**Prisma — new model (migration `add_ai_configs`):**
```
model AIConfig {
  id String @id @default(uuid())
  school_id String
  owner_id String?        // null = shared (admin-provided); set = personal
  provider String         // openrouter|openai|anthropic|google|deepseek|custom
  name String             // display
  model_id String
  base_url String?        // custom endpoints
  api_key_enc String?     // AES-256-GCM, NEVER returned to any client
  is_default Boolean @default(false)
  created_at/updated_at
  @@index([school_id, owner_id])
}
```

**Backend:**
- New `src/backend/services/AIConfigService.js`: CRUD + AES-256-GCM encrypt/decrypt (key derived from env `AI_KEY_SECRET`, fallback JWT_SECRET). Scoping: everyone sees `owner_id = null OR owner_id = me` in their school; ADMIN/SUPER_ADMIN see all rows in school. API responses strip the key (return `hasKey`, masked last 4).
- Extend `src/backend/services/AIService.js`: `generateWithConfig(configId, params, user)`, `generateWithCustom({provider, baseUrl, apiKey, model}, params)` (teacher-entered, used for the call; optionally saved as personal config), `listProviderModels(provider, apiKey, baseUrl)` (port of client `fetchAvailableModels` — OpenRouter/OpenAI `/v1/models`, Google models endpoint, Anthropic static), plus normalization to the legacy question shape (port of `normalizeQuestion` type aliases).
- `src/backend/routes/ai.routes.js` additions: `GET /configs`, `POST /configs` (shared=true admin-only; personal for teacher), `DELETE /configs/:id`, `POST /configs/:id/test`, `POST /models/refresh` (admin: provider+key → live model list), `POST /generate` (configId or custom + generation params → normalized questions), `POST /prompt` (returns the exact structure prompt — ported `buildPrompt` — for keyless users).

**Frontend (admin.html AI settings section 4400+ rewrite + questions-management.js):**
- **Admin view:** provider select + API key + **Load models** (POST /models/refresh → searchable checkbox list of current models) → "Expose selected to teachers" creates one shared AIConfig per chosen model (key encrypted once). Shared-models table with delete/test. Privacy note updated: keys stored encrypted server-side, calls proxied by the server.
- **Teacher view:** dropdown of shared models (name + provider only — no keys) OR custom config form (base URL + key + model → personal AIConfig, server-side calls; works for Ollama/LM Studio when on the same machine).
- Generator modal `generateQuestionsWithAI()` switches to `POST /api/v1/ai/generate` (configId or custom); preview + `importSelectedAIQuestions` flows unchanged; rag.js document path sends extracted text to the same endpoint.
- **Keyless path:** "No API key? Use ChatGPT/Claude" block — **Copy structure prompt** button (fetches POST /prompt output for current params to clipboard) with instructions, plus **"Import AI questions (JSON)"** in Settings → Data tab: file input `#importAIQuestionsInput` in settings.js accepting the model's raw JSON output (tolerant parse reusing ported repair logic), preview count → bulk import via existing question create/import path.
- Remove now-unneeded CSP provider entries only if client-direct code path is fully retired; keep Custom/Local note.
