## Issue 1 — Orphan games + empty Games tab

### Root cause (confirmed)
- `applyServerGameListSnapshot` in `student-workspace.js:541` and the `admin:syncGames` handler in `realtime-client.js:1155-1238` *merge* incoming games with the local cache instead of *replacing*. Any server payload that omits an id keeps the orphan alive forever.
- The server's authoritative list is in-memory only (`activeGames` Map in `game-server.js`); on a server restart, clients diverge from the DB and from the realtime state.
- The empty-tab case is mostly a side effect: after the cache is misaligned, the default filter `state.gameFilter === 'open'` (`student-workspace.js:8`) hides everything that the server has marked `live` or `completed`.

### Fix (3 layers)

**Layer A — Server: broadcast deletions**
- In `game-server.js:5401` (`socket.on('game:delete', …)`), after removing from `activeGames`, broadcast `socket.emit('game:deleted', { gameId, scope: 'global' })` to all connected sockets (except originator).
- In the `game:deleteAll` handler at `game-server.js:5059`, after clearing `activeGames` and the existing `admin:syncGames({quizGames: []})` broadcast, also emit `socket.emit('game:deletedAll', { scope: 'global' })` so individual clients drop their entries without a full re-sync.
- Add a new socket handler in `realtime-client.js` for `game:deleted` that removes the entry from `localStorage.quizGames` and dispatches `quiz:games-updated`. Reuse the same `applyServerGameListSnapshot` reconciliation path (Layer C).

**Layer B — Backend: expose DB-authoritative games list**
- `GET /api/v1/games` already exists in `src/backend/routes/games.routes.js` and returns DB rows joined with sessions. Confirm `hydrateLegacyPayload` in `bootstrap.routes.js:208-220` already includes normalized `status` (`open`/`live`/`completed`) — keep that mapping.
- No new endpoint needed; the bootstrap path is the reconciliation source.

**Layer C — Frontend: reconcile on bootstrap + on every sync payload**
1. **Bootstrap reconciliation** — In `legacy-bridge.js` (or a new `bootstrap-reconcile.js`):
   - Add a `reconcileGamesFromBootstrap(bootstrapData)` helper that:
     - Builds a `Set` of valid game ids from `bootstrapData.games`
     - Reads `localStorage.quizGames` (via `GameCore.getQuizGames()` if present, else raw key)
     - Filters out entries whose `id` is not in the valid set
     - Writes the result back via `GameCore.saveQuizGames(...)` and dispatches `quiz:games-updated`
   - Hook it into the existing bootstrap caller (search the codebase for `fetch('/api/v1/bootstrap')` / `bootstrap` / `data.games` writes). One natural seam is in `realtime-client.js` after the bootstrap ack, and another is in `student-workspace.js` `initStudentWorkspace` if it pulls the bootstrap.
2. **`applyServerGameListSnapshot` replace-not-merge** — In `student-workspace.js:541-573`:
   - If `serverGamesList` is a *complete* (global or full-school) snapshot, replace the local cache. Detect "complete" via an explicit flag in the payload (e.g., `payload.scope === 'global'` or `payload.complete === true`) that the existing `admin:syncGames` broadcast already carries.
   - If the payload is partial (teacher-scoped), keep the current merge behavior.
3. **`admin:syncGames` handler** — In `realtime-client.js:1155-1238` (both branches):
   - When `payload.scope === 'global'`, replace `mergedGames = payload.quizGames` instead of the union loop.
   - Keep the union loop only for partial scopes.
4. **Empty-tab fix** — In `student-workspace.js:8`, change `state.gameFilter: 'open'` to `state.gameFilter: 'all'`, and update `renderGamesPanel:6317-6336` to recognize `'all'` as a pass-through. Update the empty-state copy to mention "Try switching to a different filter."
5. **Defensive guard** — Add `if (!context) return;` at the top of `renderGamesPanel` (line 6308) and surface a `console.warn` (not silent) inside `getGamesStore` on JSON parse failure.

### Files touched
- `game-server.js` (broadcast `game:deleted`, `game:deletedAll`)
- `realtime-client.js` (handle `game:deleted`/`game:deletedAll`, full-replace in `admin:syncGames` for global scope)
- `student-workspace.js` (`applyServerGameListSnapshot`, `state.gameFilter`, `renderGamesPanel` guard, `getGamesStore` warn)
- `legacy-bridge.js` (or new file) for `reconcileGamesFromBootstrap`

## Issue 2 — HTTP 403 on bulk/settings

### Root cause (confirmed)
- `src/backend/routes/bulk.routes.js:931-936`: bulk write is allowed only for `admin`/`super_admin` (or `student` for `results`).
- The realtime settings panel is `data-roles="admin,teacher"` (`admin.html:4312`), so a teacher-signed-in user can change the toggle, the auto-save fires through `legacy-bridge.js:392-437 → POST /api/v1/bulk/settings`, and the server returns 403 → `notifySyncError` toast at `legacy-bridge.js:374-390`.

### Fix
- In `src/backend/routes/bulk.routes.js:931-936`, extend the gate:
  - Add a `TEACHER_WRITABLE_TABLES = new Set(['settings'])` constant.
  - Allow `req.user?.role === ROLES.TEACHER && TEACHER_WRITABLE_TABLES.has(table)` to pass.
- Audit the `settings` sanitizer at `bulk.routes.js:806-818` and `normalizeSettingsBody` at `bulk.routes.js:857-872` to make sure no admin-only keys are silently upserted by a teacher. The current keys (`realtimeEnabled`, `serverHost`, `adminSecret`, `recoveryCode`, etc.) are settings the panel exposes to teachers too, so this is consistent with the UI's intent. If `adminSecret` should be admin-only, add a per-key filter inside the sanitizer.

### Files touched
- `src/backend/routes/bulk.routes.js` (gate + `TEACHER_WRITABLE_TABLES` constant + optional per-key filter in `normalizeSettingsBody`)

### Tests
- Manual: sign in as a teacher, open the realtime settings, toggle "Enable" off/on, observe the toast disappears and the value persists in the DB (and on next page load).

## Out of scope (intentional)

- I will **not** delete `script.js`'s legacy exam runtime. It is still reachable from `openExam` (line 12551) for real graded exams, and the new modal only covers training.
- I will **not** touch the realtime settings panel's `#connection-status` element beyond the optional id fix in Issue 3, since that's a separate cosmetic bug.

## Risks and mitigations
- **Risk:** Patching `script.js` exports (e.g., `window.previewImage`) clobbers the live-exam runtime. **Mitigation:** All helpers copied into the modal are renamed with a `training` prefix so they don't shadow globals. Only the modal calls them.
- **Risk:** Bootstrap-driven game reconciliation may temporarily drop a game if the bootstrap request races with an active `admin:syncGames` payload. **Mitigation:** Add a "lastSyncSource" guard in the localStorage write — bootstrap writes only happen if no realtime sync has fired in the last N seconds.
- **Risk:** Allowing teachers to write `settings` may be wider than intended. **Mitigation:** The `TEACHER_WRITABLE_TABLES` set is explicit and the per-key filter in `normalizeSettingsBody` can block admin-only keys (e.g., `adminSecret`).

## Implementation order (suggested)

1. **Issue 3 (UI toggle)** — smallest diff, immediate visual win, no backend risk.
2. **Issue 2 (403 fix)** — one-line gate change, resolves the error toast.
3. **Issue 1 (orphan games)** — server broadcasts + bootstrap reconciliation + replace-on-global-scope. Largest touch but most isolated to game-sync paths.
4. **Issue 4 (training modal)** — biggest refactor; do last so the other fixes can be smoke-tested first.
