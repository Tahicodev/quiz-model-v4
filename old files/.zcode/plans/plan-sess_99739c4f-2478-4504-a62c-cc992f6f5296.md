# Quick-Start UX overhaul + personalized backup export/import

All exploration is complete; every defect below is confirmed in code.

## Root causes found

1. **Scroll/last-item clipped**: `.quick-start-layout` has `min-height: 420px` + `max-height: calc(88vh - 160px)` (styles.css:34433). On short viewports the `88vh`-capped `.modal-content` (`overflow:hidden`) cannot fit 420px + header + footer — the layout overflows and gets **clipped**: the step rail's last item (Games/Finish) is cut off and the panel's lower content becomes unreachable.
2. **Close button broken**: the wizard (and resetDataModal) use `class="modal-close"` — **no base CSS exists for `.modal-close` anywhere** (only `.close` and `.modal-close-btn` are styled). The button renders as an unstyled browser-default gray box.
3. **Admin Credentials** is one long section inside a single scrolling Security panel (quick-start.js:312-335) — user wants it as a **sub-tab**.

## Changes

### A. quick-start.js — Security step sub-tabs (Admin Credentials focus)
- Add `state.securitySubTab` (default `'school'`) + `switchSecuritySubTab(event, tabName)` (pattern-mirrors `switchUsersSettingsTab`, settings.js:623; exported on `window`).
- Rework `renderSecurityContent()` (quick-start.js:272): keep `<h3>` + desc, then a segmented sub-tab bar — **🏫 School Information | 🔑 Admin Credentials | 🧑‍🏫 Teachers** — and three `.qs-subtab-panel` divs (`data-sectab-panel="school|credentials|teachers"`). Existing form HTML for each section moves verbatim into its panel; active classes respect `state.securitySubTab` so re-renders (profile fetch arrival, `updateQuickStartCounts`) don't reset the chosen sub-tab.
- **Style enhancement** for the Admin Credentials panel: keep the 2-card grid, add gradient icon chips (`.qs-cred-ico`, blue shield for password, green key for recovery), refined card headers/padding.

### B. styles.css — scroll chain fix + close button + sub-tab/picker styles
1. **Scroll fix**: `.quick-start-layout` → `flex: 1 1 auto; min-height: 0;` (drop `min-height: 420px` and the `max-height: calc()` — the flex chain `modal-content(88vh, hidden) → modal-body(flex:1, min-height:0) → layout(flex:1, min-height:0) → rail/panel(overflow-y:auto)` now shrinks correctly at any viewport height; last rail item always reachable, panel always scrollable). Add `overscroll-behavior: contain` to `.quick-start-steps` + `.quick-start-panel`.
2. **Close button**: add a global base `.modal-close` rule (transparent bg, no border, 34px circle, hover tint — placed next to `.close` at ~7911, also fixes resetDataModal's ×); upgrade the quickStart-scoped one (34px translucent white pill on the gradient header with border, keep existing hover-rotate).
3. **New CSS** (appended to the quick-start section, ~34850): `.qs-subtabs` segmented bar (mirrors `.user-settings-tabs`, blue-tinted), `.qs-subtab-btn` (+`.active`, hover, focus-visible), `.qs-subtab-panel` show/hide, `.qs-cred-ico` chips, and `#backupPickerModal` styles (`.bkp-groups`, `.bkp-group`, `.bkp-item` rows, `.bkp-count` badges, warning header). Picker z-index: `#backupPickerModal[style*='flex'] { z-index: 999998 !important; }` (above settings 99999 / wizard 2900, below entity create-modals).
4. Mobile (≤700px) media block: sub-tab bar wraps, credential grid already stacks.

### C. settings.js — personalized export + import picker
1. New constant `BACKUP_GROUPS`: friendly grouped catalog of all 23 stores from `collectAllStores()` (settings.js:881): Core Content (classes, users/students, categories, questions, exams, exam link tables), Games & Tournaments (games, game_presets, tournaments, entries, history, sessions), History & Requests (results, activity, profile/account requests, notifications, teacher messages/assignments), Configuration (settings, gamification).
2. **Export**: `openExportPicker()` renders `#backupPickerModal` with checkboxes (all pre-checked), Select all / Deselect all, per-group toggle, live per-store counts; `performCustomExport()` filters `collectAllStores()` by checked keys → same v2.0 `quiz-app-backup` format (only selected stores — file stays a valid importable backup), downloads `quiz-app-backup-<scope>-YYYY-MM-DD.json`, toast + activity log entry. `exportAllData` kept as the "everything selected" path.
3. **Import refactor**: extract the per-store `__set` logic (settings.js:1042-1127, incl. questions `dateCreated` / results `dateTaken` processing) verbatim into `applyBackupStores(data, selectedKeys)`. `importAllData(inputElement, allowedKeys)` becomes: parse file → validate → open picker showing **stores present in the backup with counts** (when `allowedKeys` passed, list only those) → "Import selected" applies only checked stores → toast + activity + reload (1s). The old `confirm()` blanket dialog is replaced by the picker (explicit red warning per item: "replaces current data"). Cancel closes and resets the file input.

### D. quick-start.js — per-step separate import
- `STEP_IMPORT_KEYS`: `classes→['classes']`, `students→['users']`, `categories→['categories']`, `questions→['questions','categories']`, `exams→['exams','exam_questions','exam_classes']`, `games→['games','game_presets']`, `done→null` (full picker).
- `quickStartLoadBackup(input)` passes the current step's keys to `window.importAllData(input, keys)` (feature-detected; fallback to old behavior) — picker opens **scoped to that step** with a note that the rest is importable from Settings → Data or the Finish step.
- Per-step label: "📂 Load only *Classes* from a backup file" (dynamic). Security step unchanged (school profile is server-side, not in backups).

### E. admin.html — wiring
1. Data tab Export group: button → `window.openExportPicker()`, description updated ("choose everything or just questions, classes…"). Import group description: "choose exactly what to restore".
2. Add `#backupPickerModal` skeleton near `resetDataModal` (~line 6914); JS appends it to `body` on open (same pattern as the wizard) so stacking/dim rules behave.
3. Version bumps: `settings.js?v=…-r2`, `quick-start.js?v=…-r2`, `styles.css?v=2026-09-16-r1` (admin.html + student-workspace.html).

### Constraints preserved
No server/security changes. Backups never contain recovery-code hashes or password hashes beyond what `collectAllStores` already exports; recovery code panel untouched; picker is admin-only (Data tab is `data-roles="admin"`).
