# Full Backend Persistence + Schema Normalization Plan

## Goals
1. Persist every legacy localStorage store that has a live UI consumer
2. Normalize the Prisma schema: real `@relation` FKs everywhere, consistent `uuid()` IDs, no denormalized duplicates outside `*_json` snapshot columns
3. Add REST endpoints for the new models so no UI has to touch `setAll_sync` for those stores
4. Remove the fake-ID footguns (Date.now(), simpleHash fallbacks, "tourney-" prefixed ids)
5. Sensible delete semantics: **SetNull** on parent's FK, never cascade-lose user data

---

## Phase 2 — Backend

### 2.1 New REST route files (all under `src/backend/routes/`)

| File | Endpoints |
|---|---|
| `profile-requests.routes.js` | `GET /` (paginated; admin sees all, teacher own-classes, student own), `POST /` (student create own), `PATCH /:id` (student edits pending own), `DELETE /:id` (student cancels pending own), `POST /:id/approve`, `POST /:id/reject` (admin/teacher) |
| `account-requests.routes.js` | `POST /` (public — the signup form; rate-limited), `GET /` (admin + teacher), `POST /:id/approve`, `POST /:id/reject` |
| `game-presets.routes.js` | full CRUD; admin write, all roles read (needed by student game UI) |

| `gamification.routes.js` | `GET /` (returns the tenant's single record), `PATCH /` (admin) |
| `teacher-messages.routes.js` | `GET /?classId=` (student: only own class; teacher/admin: any), `POST /` (teacher/admin), `PATCH /:id`, `DELETE /:id` |

### 2.2 New services (all under `src/backend/services/`)
- `ProfileRequestService.js` — `createForUser`, `listForCaller`, `approve`, `reject`
- `AccountRequestService.js` — `submit`, `approve` (creates the User with bcrypt), `reject`
- `GamePresetService.js` — `listForTenant`, `create`, `update`, `delete`, `getDefaults`
- `NotificationService.js` — `push` (used internally on profile/account request create, gamification changes, teacher messages), `listForTenant`, `markAllRead`
- `GamificationService.js` — `get`, `update`
- `TeacherMessageService.js`, `TeacherAssignmentService.js` — CRUD + class-scoped listing

All seven services registered in `container.js` and exposed via `getContainer()`.

### 2.3 Wire routes into `server.js`
Add the seven `app.use('/api/v1/<name>', ...)` lines. Keep `requireAuth` as the default; only `POST /account-requests` is public + rate-limited.

### 2.4 Update `bootstrap.routes.js`
Add `profile_requests`, `account_requests`, `game_presets`, `notifications`, `gamification`, `teacher_messages`, `teacher_assignments` to `PRELOAD_TABLES`, with role-scoped filters:
- Student: only own `profile_requests`, only own class for messages/assignments, no `account_requests` / `notifications`
- Teacher: `profile_requests` and `account_requests` filtered by their `classIds`
- Admin: everything in scope

### 2.5 Bulk-route sanitizer updates (`bulk.routes.js`)
- Add real sanitizers for the seven tables (so any legacy `setAll_sync(...)` write doesn't get dropped silently while we're migrating the UI). Each sanitizer maps legacy camelCase → snake_case, runs through the same Zod schemas as the REST endpoints, then delegates to the matching service for create/update.
- Strip the legacy **`raw` passthrough** from the `results` sanitizer — drop the `raw: row` field. The other preserved keys (`examTitle`, `className`, `participants`, `leaderboard`) are still useful as a snapshot.
- For `users` sanitizer, **stop trusting `row.id` blindly** — if the id isn't a valid UUID (regex `/^[0-9a-f]{8}-[0-9a-f]{4}-4[0-9a-f]{3}-[89ab][0-9a-f]{3}-[0-9a-f]{12}$/i`), drop it and let Prisma's `@default(uuid())` fire. This is the fix for `Date.now()` ids reaching the DB.

### 2.6 `bootstrap.routes.js` mapping at read time
When preloading, convert snake_case DB rows back to the camelCase shape the legacy UI expects (`class_id` → `classId`, `numero` → `studentNumber`, `created_at` → `createdAt`, etc.) so `student-workspace.js` and the admin tables keep working without further refactor.

### 3.3 Kill the fake-id generators
- `utils.js` `generateUUID()` is already a real uuid. Keep it.
- `auth.js` `normalizeUser` (line 115) — replace `\`${Date.now()}\`` fallback with `crypto.randomUUID()` (or `generateUUID()`). The `if (typeof generateUUID === 'function')` guard already covers it.
- `games-management.js` lines 5146, 5535, 8544 — same fix: use `generateUUID()`.
- `legacy-bridge.js` `genId()` (line 144) — already OK; `crypto.randomUUID()` is the primary path. Keep the `Date.now()` fallback for ancient browsers but flag with a console.warn.

### 3.4 New IDs on new entities
For all seven new models, do **not** send `id` from the client. Let Prisma's `@default(uuid())` fire. Update the mappers to *omit* `id` when the legacy code passes a `Date.now()` string.

## Out of scope (explicitly)
- **Postgres migration**: schema stays `String @id @default(uuid())`, so it works on both. Strict `::uuid` casts only when you actually switch providers.
- **Splitting `Result.answers_json`** into a table (you said keep it JSON)
- **The realtime socket layer** (`game.handler`, `session.handler`) — those are already DB-backed through the services; no change needed
- **Removing the legacy localStorage mirror** in `legacy-bridge.js`. Keep it as a read-through cache so the UI doesn't flicker, but it's no longer the source of truth.
